# 若水本地模型可用性增强清单

本清单用于把“本地模型也要能用、好用、准确”拆成可验证的工程目标。若水不假设模型一定足够强，而是通过 Harness、上下文治理、工具约束、校验闭环和 UI 可观测性，让模型在较弱推理能力下仍能稳定完成编程任务。

## 1. 第一优先级：准确性底座

### 1.1 信息不足先问

目标：模型不能在缺少路径、目标、约束或风险信息时硬猜。

实现要点：

- 系统提示明确要求：缺少必要信息时先提出 1-3 个问题。
- 工具提示明确要求：真实环境信息必须先调用工具取证。
- 高风险操作必须进入审批，不允许模型用话术绕过。

验收：

- 用户只说“帮我改一下”时，模型应询问目标或文件。
- 用户问系统状态时，模型应优先调用只读命令，而不是凭空回答。

### 1.2 证据优先

目标：模型结论必须能回到文件、命令输出或事件记录。

实现要点：

- 工具结果回填给模型时保留路径、命令、状态、截断标记和摘要。
- Agent 回复中应优先说明基于哪些工具结果得出结论。
- 长日志只给摘要，完整日志仍留在事件历史中。

验收：

- 代码解释应引用已读取文件。
- 测试结论应来自真实测试命令。

### 1.3 修改后验证

目标：代码或配置改动后，模型应自然进入验证动作。

实现要点：

- 系统提示要求写文件后优先读回或运行相关测试。
- Harness 识别 `go test`、`npm run build`、`vue-tsc` 等验证命令，并在 `turn.summary` 中单独展示。
- 前端把验证结果从普通命令中分离展示。

验收：

- 修改 Go 后端后优先建议或执行 `go test ./...`。
- 修改 Vue 前端后优先建议或执行 `npm run build`。

## 2. 第二优先级：上下文治理

### 2.1 任务滚动摘要

目标：本地短上下文模型不用反复阅读完整历史，也能知道任务目标、已改文件和验证结果。

实现要点：

- 每轮结束后由 Harness 根据事件生成确定性任务摘要。
- 摘要包含最近用户目标、已修改文件、验证结果、最近失败或中断。
- 下轮 Context Pack 自动携带任务摘要。

验收：

- 连续多轮任务中，后续请求能看到前几轮的事实摘要。
- 摘要来自事件事实，不依赖模型自由总结。

### 2.2 相关性排序

目标：Context Pack 不再只按更新时间塞文件摘要，而是优先选择与当前问题相关的文件。

实现要点：

- 从当前用户输入和任务摘要提取关键词。
- 文件路径、摘要、符号和语言与关键词匹配时提高优先级。
- 钉住文件仍保持最高优先级。
- 超预算时只截断低优先级文件。

验收：

- 用户提到 `run_command` 时，相关工具文件优先进入 Context Pack。
- 用户提到前端主题时，前端样式或组件摘要优先进入 Context Pack。

### 2.3 手动压缩与钉住上下文

目标：用户能显式控制“让模型记住什么”。

实现要点：

- 任务页提供“压缩上下文”入口。
- 支持钉住文件、目录或文本备注。
- 钉住内容进入 Context Pack 时仍受预算控制。

验收：

- 用户钉住的关键文件优先进入下一轮 Context Pack。
- 手动压缩不会删除完整事件历史。

## 3. 第三优先级：失败恢复

### 3.1 工具调用修复

目标：本地模型工具 JSON 不稳定时，系统能给出修复机会，而不是直接失败。

实现要点：

- 工具参数解析失败时，把错误以结构化工具结果回填给模型。
- 限制重试次数，避免无限循环。
- 重试仍必须经过 Harness 权限判断。
- 同一工具调用连续失败或连续返回相同结果时，由 Harness 主动熔断并写入 `turn.interrupted`，附带可继续提示，避免模型在同一错误路径上绕圈。
- `run_command` 必须先经过路径检查，工作区外未授权绝对路径一律拦截，避免 shell 变体绕过 `list_dir` / `read_file` 的边界。

验收：

- 参数缺失或 JSON 半截时，模型能在下一轮修正。
- 连续失败或重复命中同一路径时，任务会被暂停而不是一直空转。

### 3.2 断点续跑

目标：审批、打断、重连后任务可以继续，不丢关键状态。

实现要点：

- 审批记录保存原始工具请求快照。
- WebSocket 重连按事件序号补偿。
- 打断后明确写入 `interrupted` 状态和事件。

验收：

- 审批通过后自动恢复原工具调用。
- 前端断线重连后不重复、不丢消息。

## 4. 第四优先级：回归题集

目标：用固定任务衡量“好不好用”，而不是只凭手感。

建议题集：

- 只读理解：解释一个 Go handler 的数据流。
- 小改动：修改一个 Vue 按钮样式并构建。
- 工具链：读取文件、运行测试、根据失败修复。
- 审批链：触发写文件审批，通过后继续执行。
- 中断链：运行中打断，确认状态和 UI 都正确。
- 上下文链：多轮对话后让模型接着前文改同一模块。

验收：

- 每次重要改动后至少跑一组对应题。
- 失败案例进入文档或测试，避免重复退化。

## 当前落地状态

已完成：

- WebSocket 心跳、重连和事件补偿。
- 审批通过后基于工具请求快照继续执行。
- 当前 Turn 汇总展示已编辑文件、命令和验证结果。
- Provider 上下文窗口配置与 Context Pack 用量展示。
- 提交前敏感信息检查规则。
- Context Pack 组装结果在右侧“上下文”页可见，包括预算、用量、截断状态、任务摘要状态和选中文件摘要。
- 任务滚动摘要更新会写入 `context.summary.updated` 事件，用户可以查看压缩后的摘要内容。
- Agent 已增加重复失败与重复输出熔断，连续相同工具结果时会自动中断并给出继续提示。
- 后端启动时会自动修复遗留的 `running` turn，重启后不会继续假装上一轮还在运行。

本轮新增目标：

- 每轮结束后写入确定性任务滚动摘要。
- Context Pack 文件摘要按当前输入和任务摘要做相关性排序。
- 系统提示强化“信息不足先问、证据优先、修改后验证”。
