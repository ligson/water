# Skill 管理与扩展设计

## 目标

若水使用 Skill 扩展领域知识和任务工作流，但 Skill 不能绕过 Harness。安装、启用、模型注入和后续运行时能力都必须可见、可关闭、可审计。

第一版支持：

- 在设置页上传 ZIP 安装。
- 从 HTTP/HTTPS 地址下载 ZIP 安装，兼容内网制品服务。
- 查看名称、版本、来源、摘要 hash 和关键词。
- 显式启用、停用和删除。
- 将已启用 Skill 的名称、描述和关键词作为轻量目录注入上下文；完整 `SKILL.md` 通过 `read_skill` 按需读取。
- 重新安装相同 ID 时更新包内容，同时保留原启用状态。

第一版不允许 Skill 自动执行包内脚本、动态库或二进制文件。

## 包结构

Skill ZIP 必须包含同一目录下的两个文件：

```text
my-skill/
├── skill.json
└── SKILL.md
```

`skill.json` 示例：

```json
{
  "id": "document-review",
  "name": "文档审阅",
  "version": "1.0.0",
  "description": "为长文档提取、分段读取和证据核对提供工作流。",
  "keywords": ["PDF", "DOCX", "XLSX", "PPTX"],
  "entry": "SKILL.md"
}
```

约束：

- `id` 只允许小写字母、数字、点、下划线和连字符，长度不超过 64。
- `version` 只允许字母、数字、点、下划线、加号和连字符，长度不超过 64。
- `entry` 固定为 `SKILL.md`。
- ZIP 不超过 20 MiB、最多 256 个条目。
- `SKILL.md` 不超过 256 KiB，`skill.json` 不超过 64 KiB。
- 禁止绝对路径、`..` 路径穿越和软链接。

## 安装与存储

上传和 URL 下载使用同一套校验器。安装包保存到：

```text
${WATER_DATA_DIR}/skills/<id>-<version>-<sha256前12位>.zip
```

数据库保存清单、指令内容、来源、SHA-256、启用状态和安装时间。URL 来源不会保存账号、查询参数或 fragment，避免下载 Token 进入页面或数据库。

新安装 Skill 默认停用。用户启用后，若水在每次模型请求前加载不超过 12 KiB 的 Skill 目录；任务与名称、描述或关键词匹配时，模型调用受控 `read_skill(id)` 工具读取完整说明。这样可以渐进披露能力，避免 Skill 数量增长后持续挤占本地模型上下文。

## 安全边界

Skill 内容的优先级低于若水系统规则和 Harness：

- 不能扩大工作区或外部路径授权。
- 不能跳过写入、命令、网络和 Python 权限策略。
- 不能直接修改任务完成状态。
- 不能注册未经过后端校验的任意工具。
- ZIP 内容不会被自动执行或解压到工作区。
- `read_skill` 只能读取已启用 Skill，停用后立即不可用。

HTTP/HTTPS 下载是用户解锁后发起的管理操作，支持内网地址。部署方仍应通过网络策略限制若水后端可访问的目标网络。

## 能力 Skill

MarkItDown、OCR、数据库驱动或浏览器自动化属于“能力 Skill”，因为它们不仅提供提示词，还需要运行时和工具协议。后续实现必须增加：

1. `runtime` 清单：支持的 OS/CPU、入口协议、依赖和能力声明。
2. 包签名或可信来源策略。
3. 安装预览：下载大小、文件列表、可执行内容和权限需求。
4. 独立审批：安装、首次执行、网络访问和工作区访问分别授权。
5. 进程隔离：超时、取消、资源限制、环境变量白名单和结构化输入输出。
6. 版本回滚和健康检查。

文档解析的当前默认仍是编译进 Go 后端的 `water-native`。MarkItDown 暂时保留为显式环境配置的可选增强；完成上述能力 Skill 运行时后，再迁移为可安装的文档增强 Skill，不能直接复用普通指令 Skill 的信任级别。
